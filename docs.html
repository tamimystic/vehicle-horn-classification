1. System Overview & Empirical Research Rationale

The Vehicle Horn Acoustic Data Acquisition Suite is an open-source, production-grade instrumentation system designed for field collection of vehicle horn acoustic emissions and illegal hydraulic horns in Bangladesh traffic environments (such as Dhaka metropolis corridors and highway intersections).

In high-density developing urban traffic, acoustic noise pollution exceeds hazardous levels (often surpassing 105 dBA to 120 dBA). Automated acoustic detection of illegal multi-tone hydraulic horns requires pristine, unadulterated acoustic benchmarks. Conventional smartphone recorders employ non-linear dynamic range compression (DRC), aggressive automatic gain control (AGC), and frequency-selective noise suppression, which destroy acoustic attack transients and introduce severe spectral distortion.

This software suite bypasses all digital signal processing (Zero-DSP Raw Audio) to acquire linear, uncompressed 16-bit / 24-bit PCM WAV audio alongside synchronized photographic evidence and comprehensive tabular metadata.

2. Hardware Setup & Smartphone Rig Guidelines

The system can be operated either via a smartphone (Chrome or Safari mobile browser) or a field laptop.

Recommended Field Rig Configuration:

  • Primary Capture Device: Any modern Android or iOS smartphone running Chrome 100+ or Safari 15+.
  • Acoustic Transducer: Calibrated external USB-C / Lightning measurement microphone (e.g., Dayton Audio iMM-6, Røde VideoMic Me, or factory internal smartphone mic with wind muff).
  • Wind Protection: Synthetic fur windscreen (deadcat) or high-density foam windscreen fitted over the microphone capsule to eliminate wind shear pops.
  • Physical Positioning: Standard measurement distance of 5 meters from the traffic lane, at an angle of 45 degrees relative to oncoming traffic, elevated 1.5 meters above ground level.

3. Microphone Pre-Arming (Zero-Latency Standby)

In dynamic field scenarios, vehicle horn blasts occur abruptly. If a recording system initializes the microphone hardware only upon pressing record, browser audio driver initialization and permission checks introduce a 500ms to 1500ms delay, completely missing the horn's acoustic onset transient (attack phase).

Pre-Arming Protocol: Before beginning an observation shift, tap the Arm Mic (0ms) button once in the visualizer card. Grant browser microphone permission when prompted.

Once armed, the indicator displays [ARMED: 0ms] in bright green. The audio engine runs a continuous, silent background monitoring loop that computes real-time peak dBFS and renders ambient background waveforms. When an actual horn occurs, pressing Record starts capturing samples instantly with zero milliseconds latency.

4. Session & Vehicle Metadata Entry (7-Parameter Schema)

To ensure complete scientific repeatability and prevent unlabelled orphan files, every audio clip and photograph is named according to a strict 7-parameter schema:

[SampleID]_[InstanceID]_[Location]_[Distance]_[VehicleClass]_[VehicleModel]_[VehiclePlate]_[Timestamp].wav

Form Parameters:

  • Location / Site: The geographical site or intersection (e.g., Gabtoli_Terminal, Farmgate_Cross). Use the GPS Locate button to auto-populate coordinates.
  • Distance: Geometric distance from transducer to the target vehicle (options: 1m, 3m, 5m, 7m, 10m, 15m). Default is 5m.
  • Vehicle Class: Selection across 9 standardized acoustic classes:
    1. Bus (Air/Electric Dual Pneumatic)
    2. Hydraulic_Horn (Banned extreme SPL >105 dBA multi-tone)
    3. Truck (Commercial Heavy Lorry)
    4. Private_Car (Sedan / SUV / Microbus pair)
    5. Motorcycle (High-frequency commuter disc)
    6. CNG_Autorickshaw (3-wheeler electromagnetic buzzer)
    7. Easybike_Leguna (Battery auto-rickshaw electronic chime)
    8. Rickshaw_Bell (Double metallic chime / bulb horn)
    9. Background_Traffic_Noise (Congestion idle, engine roar, tire wash - negative baseline)
  • Vehicle Name & Model: The manufacturer and model chassis (e.g., Hino_AK1J, Tata_LP410, Yamaha_FZ).
  • Plate / Vehicle ID: Registration license number (e.g., DhakaMetro-Ba-14-8923).

5. Dual Recording Modes: Tap Mode vs. Hold Mode

Different field environments and researcher preferences necessitate flexible interaction mechanics. The suite provides two independent, hardware-stabilized recording modes accessible via the mode toggle switch:

Mode Interaction Workflow Ergonomic Advantage
Tap Mode (Toggle) 1. Tap the big central button when the horn begins.
2. Button pulses red and displays a stop square.
3. Tap the button a second time when the horn ends. 		Best for relaxed handheld operation; eliminates finger fatigue during longer sustained horns (e.g., 3s-4s bus air horns).
Hold Mode (Push-to-Talk) 1. Press and hold thumb on the button while the horn sounds.
2. Lift thumb off the button the moment the horn ends. 		Fastest human reflex response; ideal for micro-taps and short commuter beeps (0.4s-0.8s). Uses Pointer Capture so sliding thumbs do not drop the record state.
Haptic Feedback: When operating outdoors in harsh sunlight, physical tactile vibration confirms actions: a single 40ms pulse upon recording onset, and a double-pulse upon recording termination.

6. Live Oscilloscope & Peak dBFS Metering

The visualizer card contains a dual-rate time-domain oscilloscope rendered on HTML5 canvas and calibrated decibel full-scale (dBFS) level meters.

  • Clean Signal (Peak < -6.0 dBFS): Badge shows SIGNAL CLEAN in green. Optimum dynamic headroom.
  • High Signal (-6.0 dBFS ≤ Peak < -0.5 dBFS): Badge shows HIGH LEVEL in yellow. Good SNR, close to full scale.
  • Clipping Warning (Peak ≥ -0.5 dBFS): Badge shows ! CLIPPING WARN ! in red. The acoustic SPL exceeded microphone ADC maximum input, resulting in non-linear waveform flat-topping. Clips marked with clipping should be evaluated and discarded.

7. Human-in-the-Loop Quality Review & Rejection

To prevent erroneous, clipped, or contaminated audio files from corrupting the dataset, recordings are never automatically committed to storage without human review.

Immediately upon stopping a recording, the Audio Quality Review card appears:

  1. The native HTML5 audio player allows instant listening to verify that the target horn is distinct and unmasked by pedestrian speech or wind pops.
  2. The exact duration (e.g., 1.42s) and target dual-layer paths are previewed.
  3. Save Audio & Photo (Green): Commits the audio and photo to the dual-layer storage hierarchy, updates metadata.csv, and increments sample counters.
  4. Discard / Retake (Red): Purges the in-memory audio buffer immediately. Counters remain intact, preserving clean sequential indexing.

8. Multimodal Vehicle Photo Capture & Segregation

To preserve clean audio loading pipelines in machine learning frameworks (e.g., PyTorch torchaudio or librosa), photographic imagery is strictly segregated from audio folders.

  • Click Snap Photo to invoke the smartphone camera or device file picker.
  • A thumbnail preview appears with an X clear button.
  • When committed, photographs are saved into a dedicated directory: Dataset/Vehicle_Photos/[SampleID]_[InstanceID]...jpg
  • The base filename matches the audio file 1-to-1, and the master CSV records the relative path in the photo_filename column.
  • Cross-Contamination Protection: When changing vehicle class, model, or plate input, the application automatically clears any previously captured photo to prevent accidental attachment to subsequent vehicles.

9. Dual-Layer Dataset Hierarchy

Academic machine learning benchmarks for vehicle acoustic classification face a severe risk of Data Leakage: if multiple horn samples from the same physical bus are randomly partitioned between training and test folds, the model learns the idiosyncratic engine hum or spectral resonance of that vehicle rather than general class features.

To enable both global class training and rigorous GroupKFold vehicle-instance cross-validation, the suite organizes every sample into two concurrent physical layers:

Dataset/ |-- Raw_By_Class/ | |-- Bus/ | | |-- BDHORN_0001_S01_Gabtoli_5m_Bus_Hino_AK1J_DhakaMetro-Ba-14-8923_20260929_003500.wav | | `-- BDHORN_0002_S02_Gabtoli_5m_Bus_Hino_AK1J_DhakaMetro-Ba-14-8923_20260929_003510.wav | `-- Motorcycle/ | |-- Instances_By_Vehicle/ | |-- Bus/ | | |-- Hino_AK1J_DhakaMetro-Ba-14-8923/ | | | |-- BDHORN_0001_S01_Gabtoli_5m_Bus_Hino_AK1J_DhakaMetro-Ba-14-8923_20260929_003500.wav | | | `-- BDHORN_0002_S02_Gabtoli_5m_Bus_Hino_AK1J_DhakaMetro-Ba-14-8923_20260929_003510.wav | | `-- Tata_LP410_DhakaMetro-Ga-11-2233/ | `-- Motorcycle/ | |-- Vehicle_Photos/ | |-- BDHORN_0001_S01_Gabtoli_5m_Bus_Hino_AK1J_DhakaMetro-Ba-14-8923_20260929_003500.jpg | `-- ... `-- metadata.csv

10. Direct Local Disk Writing (File System Access API)

On desktop Chrome, Edge, and supported Chromium mobile browsers, researchers can bypass browser download popups completely:

  1. Click Bind Folder in the metadata header.
  2. Select your local repository folder (e.g., vehicle horn classification).
  3. Grant read-write permission when prompted by the browser.
  4. The status badge displays Direct Disk Write Active.

Once bound, every saved audio clip, vehicle photo, and CSV entry is written directly to your physical hard drive in the dual-layer structure with zero download prompts.

11. Offline Persistence & Standalone ZIP Dataset Export

In field environments without stable internet connectivity or on browsers that lack direct directory binding (e.g., iOS Safari), the application relies on an enterprise-grade client-side persistence pipeline:

  • IndexedDB Offline Engine: Every recorded WAV file, JPEG image, and metadata row is stored in an encrypted client-side IndexedDB database (BDHornCollectorDB). If the phone runs out of battery or the browser tab closes, all data and sample counters are automatically restored upon reopening.
  • Pure JavaScript ZIP Generator: Click Export ZIP at the end of a field collection shift. A zero-dependency, Store-mode PKZip generator packages all audio clips, photos, and metadata.csv into a single structured archive (BDHORN_Dataset_Export_[Timestamp].zip) ready for extraction onto a lab workstation.

13. Desktop Python Suite & PyInstaller Executable Builds

In addition to the mobile PWA web app, a high-performance Python desktop application is provided for laptop monitoring rigs:

Running on Desktop:

  • One-Click Launcher: Double-click run_desktop.bat in the repository root.
  • Command-Line: Run python main.py in a terminal.
  • Web Server Mode: Run python main.py --web to serve the web application to local Wi-Fi devices.

Compiling Standalone Windows Executable (.exe):

python build_app.py

This executes PyInstaller with aggressive dependency pruning, producing a self-contained executable under dist/VehicleHornCollector/VehicleHornCollector.exe that runs on clean Windows machines without requiring a Python environment.

14. Field Troubleshooting & Frequently Asked Questions

Q1: The browser asks for microphone permission every time.

Ensure the website is loaded via HTTPS or localhost. On Android, tap the lock icon in the Chrome URL bar, select "Permissions", and set Microphone to "Allow". Tap "Install App" to install the PWA for permanent permission retention.

Q2: Audio sounds faint or low in level.

Ensure your smartphone microphone port is free of dust or pocket lint. If using an external USB microphone, verify that the hardware gain switch is set to high, and stand within 5 meters of target traffic lanes.

Q3: How do I export data from an iPhone without direct folder binding?

On iOS Safari, tap Export ZIP in the stats card at the bottom of the page. Safari will download the complete dual-layer structured ZIP file into the "Files" app, which can then be shared via AirDrop or USB cable to a workstation.

Q4: How do I run automated verification tests?

pytest tests/

All automated unit tests verify ring buffer safety, Pydantic schema validation, dual-layer folder creation, and 7-parameter filename conformance.
